# M17 on the radio: UX design

Status: built, with the differences in [As built](#as-built). The UI's M17 code is in `core/ui/` (`ui_m17.c`,
`ui_heard.c`, `ui_svc_m17.c` and the M17 parts of the shared screens); the radio core it reads is
[m17.md](../spec/m17.md). Written from the repo's UX documents ([principles.md](principles.md) P1-P10,
[information-architecture.md](information-architecture.md), [task-flows.md](task-flows.md), [wireframes/](wireframes/),
[usability-tests.md](usability-tests.md), [dual-watch.md](dual-watch.md)), [ui.md](../spec/ui.md),
[m17.md](../spec/m17.md) and [translating.md](../dev/translating.md). No other firmware's UI or source was looked at
(clean room).

## As built

What the code does where it differs from the sections below. The sections keep the design for the parts that come
later.

| Topic | Built |
|---|---|
| Build switches | The UI follows the radio core's: signatures with `CONFIG_M17_SIG`, encryption with `CONFIG_M17_SCRAMBLER` or `CONFIG_M17_AES`, SMS with `CONFIG_M17_PACKET`, the BER test with `CONFIG_M17_BERT`, Tools > Heard with `CONFIG_HEARD_LIST`. Each one off still builds (`tests/host` `uiM17Off`) |
| Addresses | Callsigns are base-40 (`m17_addr_text`); an address that is no callsign shows as `#` and 12 hex digits |
| M17 CAN and voice (Settings > Talk & listen) | Kept in `settings_t`'s `cp_flags` (bits 2-6), not in new fields: the settings record has 6 copies in RAM and one radio had no RAM for more ([settings-store.md](../spec/settings-store.md)) |
| Sign M17 calls, Send in M17 calls | Flags in the radio-wide M17 record (key 0x0A06), written by a storage job (`m17_wide_save`) |
| Signing key shown | The one `radio_m17_key` reports. The fingerprint is `m17_key_fp` over the compressed public key, 4 groups of 4 hex digits |
| Receive | A channel plays its own CAN; digital monitor (Quick 5) plays every CAN on a plain channel or the VFO |
| Talk target on a stored M17 channel | The radio core has no temporary destination for a stored channel. OK on a station says "Hold OK to set it"; hold OK writes the station as the channel's destination ("Default now: N0CALL"). On the VFO, or a channel switched to M17, the destination is temporary as designed |
| The radio's M17 settings (the VFO's and a channel switched to M17's) | One copy in RAM (`radio_m17_settings_t`). The UI keeps it as the design says: on a channel switched to M17, Quick CAN and rate change it alone ("CAN 3 for now"), never Talk & listen's; in the VFO they are the VFO's own and Talk & listen's ("CAN 3"). A destination, digital monitor, and on a channel the CAN and rate, are for now: **Back** on Home ("Changes undone"), leaving the VFO, or leaving the channel puts the settings back where they start from (Talk & listen's CAN and voice, the CAN's squelch, All call; `ui_app.c` `m17_settings_reset`). Settings the debug link sets there (op 44 sub 0) are changes for now the same way. A scan or dual watch moving the receiver is no leaving: where it ends is judged once it has, against the channel the changes were made on (`m17_settings_track`). In dual watch the selected channel counts: selecting the other one while it is off the settings (FM, a stored M17 channel) keeps them, as the first is still watched, and so does a setting changed there (it stops the watch for a moment); selecting it while it is on them too (switched to M17 for now, or the other VFO in M17), or switching it to M17, ends them, as one copy would carry them to it. Each change of one field starts from `radio_m17_settings_next` (the request still waiting for the radio task, else the settings in force), so two before the radio task's turn both last |
| Quick CAN, rate, digital monitor on a stored channel | "Set it in the channel editor". Quick 6 on an encrypted stored channel writes encryption off ("Privacy off") |
| PTT refused for want of a callsign | OK opens the callsign entry while the refusal shows and for 5 s after PTT is released (the hint is gone by then); after that OK is the menu again |
| Reply window, one-shot PTT | Not built: PTT sends to the destination in force. Talk back goes through Recent, the picker or Call Details' actions |
| Channel editor | CAN (0-15, or Any), Rate, Destination (the picker, or a typed callsign), Encryption On/Off. The CAN label is an untranslated "CAN", as "RAN" for NXDN. The key and the encryption type are the Codeplug Editor's; turning encryption on without a key says "No key: set one in the editor" |
| Call Details | A text page like About: no title while idle; the signature's word is the second line, after From |
| Tools > Heard | A list of the stations heard (any mode; M17 is its only source so far) and a page per station; built with `CONFIG_HEARD_LIST`. The page keeps the station it opened on by who it is (`radio_heard_find`), not by its row: every reception reorders the list. Once newer stations push it out, the page says "No longer in list" and has no target: # offers nothing there |
| BER test page | Takes BERT mode whenever it is on top: on opening, when a screen over it (Quick settings, the picker) closes, and when the channel becomes M17 while it is open; gives it back whenever another screen is on top. The counts line's alternates are built whole, so a long count is never cut |
| Call text | The Settings value shows the stored text as the display's text (UTF-8, `utf8_to_display`; control bytes dropped). A text another tool stored with more than printable ASCII opens as its ASCII part; OK with nothing typed keeps it as stored |
| Dual watch | An M17 pane shows the caller and "M17 call"; no CAN or destination |
| Messages | No shared `core/msg` store: M17 SMS is a provider over the radio core's inbox. Sending needs an M17 channel ("Send from an M17 channel") that doesn't encrypt ("Privacy on: messages can't be encrypted", 15.3) |
| Strings | Every key of 18.1 except `CHAN_LABEL_CAN` (a literal, above) and `CHAN_VALUE_ENC_NO_KEY` (the toast above). New: `M17_WHY_STORED_EDITOR`, `M17_WHY_STORED_HOLD_OK`, `MSG_WHY_M17_CHANNEL`, `MSG_WHY_PRIVACY_ON`, `HEARD_TITLE`, `HEARD_EMPTY`, `DENY_WHY_ENC_NOT_READY` ("Encryption not ready: try again"), `DENY_FIX_WAIT_RETRY` ("Wait a moment, then PTT"), `CALL_VALUE_SIG_OTHER` ("{Signed by another station\|Other signer}": Recent's word for a call another station signed, where the signer isn't kept) |
| Chinese | The catalog uses only the characters the CJK face has; "Sig" stands for signature |
| Reflector (22) | Tools > M17 reflector (`m17-reflector`, `CONFIG_NET_M17`, [m17-ip.md](../spec/m17-ip.md) 7.1) sits above M17 BER test, not after it, so the BER test and Heard keep their key paths. Its state is the text above the rows; the rows are Reflector (name and module, typed with the callsign entry), Address (IPv4: the radio has no name lookup), Port, Listen only, Link / Unlink. What is typed is RAM only. Home's place line says "Linked M17-M17 C" where the layout has a zone line; the picker offers ECHO and INFO while linked. New keys: `TOOLS_ROW_M17_REFLECTOR`, `M17_TITLE_REFLECTOR`, `M17_LABEL_REFLECTOR`, `M17_LABEL_REFL_ADDRESS`, `M17_LABEL_REFL_PORT`, `M17_LABEL_LISTEN_ONLY`, `M17_ROW_LINK`, `M17_ROW_UNLINK`, `M17_BODY_*` (the states), `M17_WHY_REFL_*`, `M17_TOAST_LINKING`, `M17_TOAST_UNLINKED`, `HOME_LABEL_M17_LINKED`, `PICKER_CHIP_REFLECTOR` |

Notation:

- **[reuse]** an existing TR key or screen; **[new]** a new one; **[gen]** an existing shared piece generalized (one
  stack: no M17 copy).
- `{Long|Short}` is a text with alternates (`TEXT_ALT_OPEN ... TEXT_ALT_NEXT ... TEXT_ALT_CLOSE`, `font.h`): the
  longest that fits is drawn.
- Wireframe fonts are the real ones from `ui_layout_init()`:

| Class | small (lists, chips, lines) | medium (talk line) | large (channel, caller) | List rows |
|---|---|---|---|---|
| 128x64 mono | 5x8, 25 columns | 6x12, 21 | 8x16, 16 | 5 |
| 160x128 / 160x120i5 color | 6x12, 26 / 25 | 8x16, 20 / 18 | 12x24, 13 / 12 | 7 (5 in a wide language) |
| 240x320 color | 8x16, 30 | 12x24, 20 | 16x32, 15 (12x24, 20 without `FONT_XL`) | 11 |

A callsign is at most 9 characters, so it fits the large font of every class whole and is never shortened.

## 1. Decisions at a glance

| # | Decision | Why |
|---|---|---|
| D1 | M17 is one more digital mode on the same screens: Home, the call screen, Recent, Messages, the talk target picker, the channel editor, Quick settings, dual watch. No "M17 menu" | P1, P6 (settings by intent, never by protocol), one stack (AGENTS.md rule 4) |
| D2 | Addresses travel in the UI as a mode-neutral `ui_addr_t` (a DMR ID / talkgroup, or a 48-bit base-40 callsign); text is made only when drawn | `ui_target_t`, `ui_recent_t`, `ui_msg_t` assume `uint32_t` IDs today, so an M17 callsign does not fit without a shared address type |
| D3 | The DMR call screen becomes the shared call screen: a `ui_call_t` built per mode, drawn by one function. M17 is its second user | M17 needs the room (via, text, position, signature); no second call screen |
| D4 | The message inbox becomes a provider table under `ui_svc_msg_*`; DMR, APRS and M17 are providers. The Messages screens see one list of `ui_msg_t` with a `ui_addr_t` | The answer to "generalize `ui_msg_t` without forking" (section 15.1) |
| D5 | Signatures are shown in words on the call screen while the call runs ("Signed: checked at end"), on Home's last-heard line, in Recent and on Call Details after it ends. A bad result also raises a banner; a good one is quiet | P9 (failure never silent, success quiet), P5 (a word for every color) |
| D6 | "Not signed" is shown only for a station whose public key the radio holds; other unsigned calls (almost all M17 traffic) show nothing | An attacker strips a signature; a warning everywhere would be noise |
| D7 | No trusted clock: the radio never calls a signed call fresh. Call Details says "Time check: not done, no clock" | The radio has no trusted time source, so a signed timestamp cannot be checked ([m17.md](../spec/m17.md) 7.4) |
| D8 | Encryption shows as "Priv" (the existing privacy marker, privacy blue) on Home, TX and RX lines; the kind ("Scrambler 16-bit", "AES-256") only in the channel editor and Call Details. The scrambler is never called "encrypted" | One term per thing (P10); crypto.md 8 |
| D9 | Settings rows go to their intent group, each named with "M17" and found by Find's "M17": callsign and call text in My radio, CAN and voice in Talk & listen, position in Location, signing and keys in Privacy, the BER test in Tools | P6; Find covers "all M17 settings in one place" |
| D10 | PTT without a callsign is refused with "No M17 callsign set" / "OK set callsign"; OK there opens the callsign entry | P9; one press to the fix (precedent: "OK stop hotspot") |
| D11 | The destination is the M17 talk target: the same three lifetimes (one-shot, temporary, permanent), the same picker (long `#`, Quick 8), "All call" for broadcast | P2, IA 1 |
| D12 | Typed text "ALL" is refused as a destination ("For everyone, pick All call"): base-40 "ALL" is a callsign, not broadcast | A trap that would silently send to nobody |
| D13 | M17 contacts are not on the radio in version 1 (the Targets family has no editor support). Save as contact on an M17 station is dimmed with the reason | The Targets family has no editor support for M17 addresses yet |

## 2. Shared pieces first (one stack)

Each item is a refactor that is behavior-neutral for DMR, P25, NXDN and APRS, proved by the existing `uiFlowTest`
flows and an unchanged UI gallery (`make -C tests/host ui-gallery` must not change a PNG), and only then gets its M17
branch. Same order as [adding-a-mode.md](../dev/adding-a-mode.md) 3.1 (radio core table first).

### 2.1 `ui_addr_t` [gen]

```
typedef struct {
	uint8_t kind;		// UI_ADDR_NONE, UI_ADDR_DMR_ID, UI_ADDR_DMR_TG, UI_ADDR_CALL (base-40, 48 bit)
	uint8_t net;		// the bearer that reaches it: UI_NET_DMR, UI_NET_M17, UI_NET_APRS
	union { uint32_t id; uint8_t call[6]; };
} ui_addr_t;		// 8 bytes
```

- `ui_target_t` (`ui_nav.h`), `ui_recent_t`, `ui_msg_t`, `ui_event_t` (its banner target) take a `ui_addr_t`
  where they have `id` (+ `group`) today. A DMR target keeps exactly what it has now.
- Text is made only where it is drawn: `ui_sb_addr(sbuf_t *, const ui_addr_t *)` gives "TG 91 World" / "Joe
  9991234" / "N0CALL" / "All call" / "#EE6B28000001" (an extended address: `#` and 12 hex digits, m17.md 13).
- The base-40 codec is named by what it does and lives in a generic place, `core/support/base40.{c,h}`
  (`base40_encode`, `base40_decode`, `base40_valid_char`), used by `core/m17` and the UI. APRS callsigns (A-Z, 0-9,
  `-`, at most 9 characters with the SSID) fit it too, so the APRS inbox can move onto `UI_ADDR_CALL` later.
- RAM: Recent grows from `uint32_t src, dst` to two 8-byte addresses, +8 B an entry, about 100 B for 12 entries.

### 2.2 The call screen: `ui_call_t` [gen]

`draw_dmr_call()` (`ui_screens.c`) becomes `draw_call(const ui_call_t *)`. Builders per mode fill the struct from the
view: `call_from_dmr()` (today's logic, unchanged output) and `call_from_m17()`. `dmr_call_screen()` becomes
`call_screen(v)` asking each built mode. P25 and NXDN stay on Home's activity region for now; they can move to the
call screen later with a builder of their own.

```
typedef struct {
	bool tx, played, emergency, late;
	char title[24];		// RX: where the call goes ("TG 91 World", "All call", "To you"); TX: the target
	char caller[24];	// RX: who (large); TX: the state word ("TALKING", "SIGNING")
	char why[32];		// why it isn't played (warn), or ""
	char via[24];		// "via M17-M17 C", or ""
	char sig[32];		// signature line, or ""
	uint8_t sig_color;	// UI_C_RX, UI_C_WARN, UI_C_DIM
	const char *text;	// talker alias / M17 text, drawn in quotes; NULL: none
	char pos[24];		// "12.3 km NE", or lat/lon, or ""
	char detail[40];	// "TS1 CC1 late ENC" / "CAN0 3200 Priv late"
	int16_t dbm;
} ui_call_t;		// static in ui_screens.c, about 230 B: not on the UI task stack
```

Line order is fixed per mode by the builder; `draw_call` draws lines top down until the hint row and drops the rest
(section 4.2 gives M17's order).

### 2.3 The talk target picker over modes [gen]

`picker` (`ui_menus.c`) asks the mode for its rows. DMR keeps its rows. On an M17 channel or the M17 VFO:
"Current" (the destination in use), "All call", the M17 stations in Recent (newest first, up to 8), "Type a
callsign...". The same rows serve the channel editor's Destination row through `chpick` (section 10). The refusal
"Talk target: DMR channels only" becomes "Talk target: DMR and M17 only" (new key, section 18).

### 2.4 Text entry with a character set [gen]

`text_open()` takes a character set: `TEXT_SET_ANY` (today), `TEXT_SET_CALLSIGN` (M17 base-40: A-Z, 0-9, `-`, `/`,
`.`, space; upper case only), `TEXT_SET_ASCII` (printable ASCII, for M17 call text). The set filters the keypad
cycles (key 1: `- / . 1`, key 0: space and 0, 2-9: their letters then digit; `#` cycles ABC / 123 only), the Up / Down
stepping on radios without a keypad (space, A-Z, 0-9, `-`, `/`, `.`), and pasted defaults. New screen def
`callsign` (section 12); `aprs-to` can move onto it later with an APRS set.

### 2.5 Quick tiles per mode [gen]

`ui_quick_kind()` has an FM and a DMR table today; P25 and NXDN use FM's. It gets a table per mode, and M17's is in
section 9. New tile kinds `QT_RATE` and `QT_CAN`; `QT_HEAR_ALL`, `QT_PRIVACY` and `QT_TALK_TO` call a mode's service
(`ui_svc_hear_all`, `ui_svc_privacy`, `ui_svc_talk_to` route by `v->ch.mode` in `ui_svc_radio.c`).

### 2.6 Call Details [new, generic]

A page any mode can fill (`call-details`, section 6). Version 1: M17 only; "Call details" appears in caller actions
only where the mode provides details.

### 2.7 Feature bits

One bit, `UI_FEAT_M17` (next free: bit 24), as `UI_FEAT_NXDN`. The sub-features are asked through
`ui_svc_m17_caps()` (weak stub: 0), bits `UI_M17_SIG`, `UI_M17_ENC`, `UI_M17_SMS`, `UI_M17_BERT`, following the build
switches (`CONFIG_M17_SIG`, `CONFIG_M17_SCRAMBLER`/`CONFIG_M17_AES`, `CONFIG_M17_PACKET`, `CONFIG_M17_BERT`;
[build-config.md](../build-config.md)). Every screen and row in this document is built only with its switch, and the build
stays clean with each off (AGENTS.md rule 5).

## 3. Home on an M17 channel (and the M17 VFO)

Regions as IA 3, unchanged.

| Region | M17 |
|---|---|
| Status strip | mode word `M17` (`ui_mode_name`, `codeplug_kind_name`; never translated); RX outside Home: "RX N0CALL" |
| Place | zone, channel number and name; in the VFO the frequency and "VFO" |
| Talk line | arrow and the destination: "All call", "W1AW", "M17-M17 C", "ECHO"; the reply window "N0CALL (8s)" with the inverted reply glyph; a temporary destination has the dot |
| Chips | power, `CAN<n>`, `3200`/`1600`, then `DMon`, `Priv`, `Sig`, own callsign (below) |
| Activity | idle: the last M17 call heard (section 3.3); RX: the call screen (section 4); TX: the TX screen (section 5) |
| Hint | as Home's today: `OK Menu  * Quick  # N0CALL` (the last caller's callsign) |

### 3.1 Talk line overrides, first that applies

| Condition | Talk line | Color |
|---|---|---|
| a stored M17 channel in a build without M17 | "Mode: not in this build" [reuse] | warn |
| RX only | "RX only" [reuse] | warn |
| no TX frequency | "No TX frequency" [reuse] | warn |
| no own callsign (or one that isn't valid) | "No M17 callsign" [new] | warn |
| otherwise | the destination | fg (warn during the reply window) |

The destination text: broadcast `FFFFFFFFFFFF` is "All call" [reuse `VALUE_ALL_CALL`]; a standard address its
base-40 text; an extended one `#` and 12 hex digits.

### 3.2 Chips

Left to right; each is drawn whole or not at all, so the right-most go first on a narrow display (as `draw_chips`
does today):

| Chip | When | Text | Color |
|---|---|---|---|
| Power | always | `Lo` / `Hi` / ... (`ui_power_name`) | fg, warn with dot when temporary |
| CAN | always | `CAN0` ... `CAN15` (radio form, no space, like `CC1`) | fg, warn with dot when temporary |
| Rate | always | `3200` or `1600` | fg, warn with dot when temporary |
| Digital monitor | RX takes every CAN | `DMon` [reuse `HOME_CHIP_DMON`] | warn |
| Privacy | TX encryption on | `Priv` [reuse `HOME_CHIP_PRIVACY`] | privacy blue |
| Signing | Sign M17 calls on and the key is usable | `Sig` [new `HOME_CHIP_SIGNED`] | fg |
| Own callsign | set | `W1AW` | dim |

Worst case at 128x64: `Lo CAN15 1600 DMon Priv Sig` is 27 columns, so `Sig` and the callsign drop; at 160x128 26
columns, the callsign drops. The callsign is also on the TX screen and in Settings, so losing it here costs nothing
critical.

### 3.3 Idle activity: the last M17 call

From `radio_m17_view_t` (the radio core keeps the last call's originator, destination, time, signature result, as
DMR keeps `dmr.last`).

- Two lines where the region has them: line 1 the originator (fg) and, right-aligned where it fits, the signature
  short word ("Sig OK" in the RX color, "Sig failed" / "By W1AW" / "Not signed" in warn); line 2 the destination, the
  distance where known and the age, dim: "All call 12 km 11s ago".
- One line (128x64): "N0CALL" left, "All call 2m" right; a failed or mismatched signature takes the right part
  instead, in warn: "N0CALL  Sig failed 2m".
- Nothing heard: "No calls heard yet" [reuse `EMPTY_NO_CALLS_HEARD`].

### 3.4 Large text

Line 1 the channel name (VFO: frequency), line 2 the arrow and destination (as DMR's target), short form never
needed (9 characters).

### 3.5 Dual watch pane

| Row | M17 |
|---|---|
| 2 | idle: the arrow and destination; the VFO: "VFO M17"; a call: the caller's callsign, or "M17 call" [new `CALL_VALUE_M17_CALL`] before the LSF is known, with the RX pill |
| 3 | frequency and `CAN0` |

A signature failure on the pane not selected still raises the banner (section 4.5).

## 4. Receiving

### 4.1 Who called and where

| Item | Rule |
|---|---|
| Originator (the big line) | callsign field 1 of extended callsign META when the LSF carries it, else SRC |
| Via | callsign field 2 (a reflector's name) when present: "via M17-M17 C"; else SRC when it differs from the originator (a repeater or gateway): "via W1RPT"; else none |
| Title (where it goes) | DST: "All call" (broadcast), "To you" [reuse `CALL_VALUE_TO_YOU`] when DST is our callsign, else DST's text ("M17-M17 C", "W1AW", "ECHO") |
| Before the LSF is known (late entry, up to 6 frames, 240 ms) | big line "M17 call", no title, detail `late` |
| Reply window | only for a call to us (DST = our callsign): PTT replies to the originator for the reply window, Home shows "N0CALL (8s)" as DMR does |

### 4.2 Call screen lines, M17 order

Drawn top down until the hint row:

1. Caller (large): the originator; "M17 call" before the LSF. Warn color when the call isn't played, dim as DMR's
   `RDMR_RX_OTHER`.
2. Why it isn't played, warn, if not played:
   - "Encrypted: not played" [reuse `CALL_WHY_ENCRYPTED`]: AES without a key, or AES not in this build.
   - "Scrambled: not played" [new]: scrambler without a key, or not in this build.
   - "Other CAN: not played" [new]: the CAN differs and the channel takes its own CAN only; the detail line names
     the CAN heard so the user can set it (Quick 3) or take every CAN (Quick 5).
   - "Data only: no voice" [new]: a stream of data type `01`.
3. Via line, small.
4. Signature line (section 4.4), small, its color from the table.
5. Text META in quotes, small, up to 2 lines (up to 4 on 240x320), cut at the end with an ellipsis. Shown as it
   arrives: blocks already heard, an ellipsis for those still to come. Always shown (it is what the caller chose to
   send); not tied to "Show talker alias".
6. Position from GNSS META: "12.3 km NE" (`sb_range`, with our own fix), else latitude and longitude (`sb_degrees`).
7. Detail line, dim: `CAN0 3200 Priv late` with the signal at the right ("-71 dBm"). `Priv` when the call plays
   decrypted or descrambled. `1600` for voice and data. `late` [reuse `CALL_CHIP_LATE`].
8. The signal meter, where a whole row is left (240x320).

Hint: "PTT replies" [reuse `HINT_PTT_REPLIES`].

A signed call that isn't played (encrypted, no key) is still checked: the stream hash covers the ciphertext, so the
signature result shows after the end as for any call.

### 4.3 Text, UTF-8 and the fonts

M17 text (META text and SMS) is UTF-8. Into the display's one-byte text: ASCII as is; U+00A0-U+00FF as its Latin-1
byte (drawn with the accent in a build with a language, folded without, as today); a character the CJK face has stays
3-byte UTF-8; anything else becomes `?`. One generic helper, `utf8_to_display()` next to `gfx_utf8_next`, also used
by the SMS path (section 15).

### 4.4 Signature states

| State | When | Call screen line | Color | After the call |
|---|---|---|---|---|
| Unsigned | TYPE bit 11 clear, no key on file for the originator | none | | nothing |
| Unsigned, key on file | TYPE bit 11 clear, the radio holds a public key for the originator | "Not signed" [new] | warn | last heard "Not signed" (warn); Recent row warn |
| Signed, running | bit 11 set, stream from FN 0 | "{Signed: checked at end\|Signed}" [new] | dim | |
| Checking | after FN `FFFF`, the check running (20-60 ms) | "{Checking signature\|Checking}" [new] | dim | (seldom seen) |

Wording rule from crypto.md 6.6: a failure doesn't accuse ("Signature check failed", not "forged"): FEC errors look
the same as tampering. A destination different from DST is no reason to warn (gateways rewrite DST).

Freshness: without a trusted clock (no GNSS UTC) the radio never says a call is in time; Call Details says "Time
check: {Not done: no clock|No clock}". With GNSS UTC: "In time" / "Too old". A timestamp of 0 (a sender without a
clock): "Signed at: Not sent".

## 15. SMS over M17 packet mode

### 15.1 One inbox without forking `ui_msg_t` [gen]

Today: `ui_msg_t` is DMR-shaped (`uint32_t src`, `bool group`), `ui_svc_msg_*` are implemented on the DMR data
service only, and the Messages screens merge the APRS store by hand (`msg_row`, `MSG_APRS_ARG`, `aprs_composing`).
Adding M17 the same way would be a third hand-merged branch in every message screen. Instead:

1. `ui_msg_t` takes the address and loses the DMR fields:

   ```
   typedef struct {
   	ui_addr_t peer;		// sender, or the recipient of one we sent (kind and net say DMR ID, TG, callsign; bearer)
   	bool unread, sent, cut;	// cut: longer than UI_MSG_TEXT_MAX, kept to that
   	uint32_t age_ms;
   	char name[17];		// a contact's name if known (DMR), else ""
   	char text[UI_MSG_TEXT_MAX + 1];
   } ui_msg_t;
   ```

2. A provider table in a new `core/ui/ui_svc_msg.c`:

   ```
   typedef struct {
   	uint8_t net;					// UI_NET_*
   	uint16_t (*count)(void);			// newest first
   	bool (*get)(uint16_t i, ui_msg_t *out);
   	void (*read)(uint16_t i);
   	bool (*del)(uint16_t i);
   	bool (*send)(const ui_addr_t *to, const char *text);
   	bool (*reply)(uint16_t i, const char *text);
   } ui_msg_provider_t;
   ```

   DMR's lives in `ui_svc_data.c` (today's code), APRS's in `ui_svc_aprs.c`, M17's in a new `ui_svc_m17.c`; each is
   in the table only with its switch. `ui_svc_msg_count/get/read/delete` walk the providers and merge them newest
   first (the merge `msg_row` does today, moved out of the screen); an index is the merged row. `ui_svc_msg_send(to,
   text)` and `ui_svc_msg_reply(i, text)` go to the provider of `to.net` / of row i. `ui_svc_msg_unread` sums.
3. The screens (`messages`, `message`, `message-read`, `compose`, `message-text`) lose their APRS branches and treat
   every row the same; what differs (APRS's "Request acknowledgment" and "Include position" rows) is a provider
   capability flag. Banners read the merged index.
4. Step order: (a) refactor with DMR and APRS only, proved by the existing message flows and the APRS flows, no
   behavior change; (b) add the M17 provider.

The M17 inbox itself is small RAM in `core/radio/radio_m17.c` (`CONFIG_M17_PACKET`): 4 messages of up to `UI_MSG_TEXT_MAX` (143)
bytes, about 640 B, oldest dropped. It cannot live in the memory M17 borrows (lent only while M17 runs; messages
must outlive a mode change). A shared store in `core/msg/` for DMR and M17 together would save the DMR inbox's copy
and is the better end state; it touches the DMR data service, so it is proposed, not required.

### 15.2 Receiving

- Packet type `05`: the text (UTF-8, its zero byte dropped), converted (section 4.3) and kept to 143 bytes at a
  character boundary; `cut` set when longer (M17 allows 821).
- Banner as today: "Message from N0CALL" [reuse `MSG_BANNER_FROM`] and two lines of the text; `#` opens it; the
  message tone; the unread count on the strip.
- Messages list rows as today: "N0CALL: Meet at the north lot" and the age; unread in warn.
- The message page as today ("From N0CALL, 2m ago" and the text); a cut message's Full message page ends with
  "[Cut: too long for this radio]" [new `MSG_BODY_CUT`].
- Message rows: Reply "OK", Reply "On my way", Call (talk to N0CALL for now), Delete. Reply off an M17 channel: the
  rows are dimmed, OK says "{Send from an M17 channel\|M17 channels only}".
- Other packet types, APRS (`02`) among them, only make a Recent row "Data" and count on the debug link. APRS over
  M17 is not written: the spec does not define its format, and no switch exists for it
  ([m17.md, Not written](../spec/m17.md#19-not-written)).

### 15.3 Sending

- Messages gets a row "New M17 message" [new] (after "New APRS message"), on an M17 channel with `UI_M17_SMS`;
  elsewhere dimmed with "{Send from an M17 channel\|M17 channels only}".
- On a channel set to encrypt (`RADIO_M17_TX_ENC`) every way to a message is dimmed the same way and says
  "{Privacy on: messages can't be encrypted\|Privacy on: no messages}" [new `MSG_WHY_PRIVACY_ON`]: packet mode has
  no encryption, and the radio core never sends in the clear what the channel asks to encrypt
  ([m17.md 17.3](../spec/m17.md#173-transmit)). The provider's `send_ok` gives the reason; the composer checks it again at send,
  so a channel changed while it was open says why, not "Couldn't send: try again".
- From a station: caller actions > Message, a Recent row's actions, the message page's replies.
- Composer (`compose`, title "To N0CALL", or "To Callsign" before one is typed): row 1 "To callsign" [reuse
  `MSG_LABEL_TO_CALLSIGN`] with the callsign or "Enter" [reuse] (opens `callsign`); then the canned texts; then
  "Write..." (up to 143 characters).
- Sending: Home's activity "SENDING" with the TX pill; toast "Sending to N0CALL" [reuse `TOAST_SENDING_TO`].
- Results as banners: "Sent to N0CALL" [reuse `BANNER_SENT_TO`]: M17 packets carry no delivery report, so never
  "Delivered"; "Not sent to N0CALL" [new] with "Channel busy: send again" [new] when the channel stays busy.
- Text out: ASCII as typed; a Latin-1 character (canned texts in a translation) is encoded as UTF-8.

## 17. Fit on the three display classes

| Text | Longest | 128x64 | 160x128 | 240x320 |
|---|---|---|---|---|
| Callsign, large | 9 | 16 cols: whole | 13: whole | 15/20: whole |
| Talk line, medium (arrow + destination) | 10 ("→M17-M17 C"); "→No M17 callsign" 16; reply "N0CALL (30s)" 12 | 21 | 20 | 20 |
| Chips | `Lo CAN15 1600 DMon Priv Sig W1AW…` | `Sig`, callsign drop | callsign drops | whole |
| RX title in the merged strip | "M17-M17 C" 9 | ~19 after the pill | ~20 | own title row |
| Signature line, small | "Signed: checked at end" 22; "Signed: no key to check" 23 | 25: long form | 26 | 30 |
| Text META | 52 + quotes | 1 line, cut | 2 lines (52 just fits without quotes; cut with them) | up to 4 |
| Detail + signal | "CAN15 1600 Priv late  -71 dBm" 29 | the signal drops first, then `late` | the signal drops (26 columns) | whole |
| Encryption value in a row | "Scrambler 24-bit" 16 + label 10 | short form "Scrambler 24" | long | long |
| BER counts | "Errors 12345 of 1234567 bits" 28 | " bits" drops, then the line becomes "12345/1234567" | whole | whole |

- Lines on the call screen at 128x64: three small lines under the caller. The order in 4.2 puts the reason a call is
  silent first, then the via, the signature, the text: what matters most survives.
- Chinese (160 px class): 16 px lines leave 4 small lines on the 160x128 call screen; the order still holds. 128x64
  has no Chinese (`BOARD_UNSUPPORTED`).
- No middle ellipsis anywhere: callsigns always fit; texts are cut at their end (META text, message previews), which
  `uiSim --layout` accepts.
- Worst-case content for `uiSim --layout` and the gallery (`sim_worst`): 9-character callsigns with `-`, `/`, `.` and a
  space ("M17-M17 C"), a 52-character META text, CAN 15, 1600, privacy and signing on, a 9-character via, a 3-digit
  distance, every signature state, a 143-byte message with `cut`.

## 23. Open points

1. Fingerprint format (8 bytes of SHA-256 over X‖Y, 4x4 hex): confirm with the crypto workstream and use the same in
   the editor (crypto.md open question 8).
2. The signature time window (300 s) is fixed in version 1; a setting only if users ask (it means nothing without a
   clock).
3. "Not signed" with a key on file assumes the keyring is indexed by callsign in RAM or cheap to search per call;
   station keys are system entries ([m17-codeplug.md](../spec/m17-codeplug.md) 4.2), a few dozen at most, so a linear
   search at call start is fine.
4. Whether the M17 inbox becomes the shared `core/msg` store now (saves the DMR inbox's RAM twice) is the DMR data
   owner's call; the provider table works either way.
5. The Codec 2 1600 data channel carries nothing from this radio in version 1, and what other stations send in it is
   not shown: "1600 + data" is the spec's name for the mode, not a promise. Revisit when the spec defines its use.
6. RX "Other CAN: not played" assumes the receiver squelches on CAN by default (the spec's "may"). If the radio
   core decides to play every CAN by default, the channel's CAN row starts at "Any/0" and the message never shows
   unless the user sets a CAN.
7. Flash on the 160x128 radios with about 42 KB free: the UI's M17 part (estimated 5-7 KB with English, plus about 2
   KB per language) must be measured per sub-switch; the signature, encryption, SMS and BER screens go with their
   switches so a tight board can keep voice and callsigns only.
